# Development Rules

Before implementing any task:

1. Read all relevant documentation in `docs/forgemind-architecture/`.
2. Follow the approved folder structure.
3. Do not rename existing files or folders without approval.
4. Do not change APIs unless the task requires it.
5. Keep commits focused on a single feature.
6. Explain every file that is created or modified.
7. Add appropriate error handling.
8. Write maintainable, modular code.
9. Avoid duplicate logic.
10. If documentation and implementation conflict, stop and report the conflict instead of guessing.
